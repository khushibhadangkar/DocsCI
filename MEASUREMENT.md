# DocsCI Quality and Efficiency Measurement Framework

This guide outlines the methodology for measuring documentation review efficiency, error reduction, and AI verification catch rates when introducing DocsCI into an engineering organization.

> [!IMPORTANT]
> The measurement tables below are intentionally left unpopulated. Technical writers, documentation engineers, and interns should conduct live trial audits on their specific documentation repositories and record actual measured values. Do not invent metrics.

---

## 1. Methodology and Measurement Dimensions

To quantify the operational impact of DocsCI, measure three distinct dimensions:

### A. Editorial Review Time (Minutes per 1,000 Words)
- **Baseline (Manual Review)**: Have a technical writer review a pull request containing documentation updates without automated linting or link checking. Measure time spent checking heading hierarchy, active voice, terminology compliance, and dead links.
- **DocsCI Automated Review**: Run `docsci lint docs/ --strict` and `docsci links docs/`. Measure writer time spent reviewing only the remaining content nuances and approving the pull request.
- **Metric**: Time saved = `(Manual Time - DocsCI Time) / Manual Time * 100%`.

### B. Violation Reduction (Count of Defects Caught Before Production)
- **Baseline Scan**: Run `docsci report docs/ --output baseline.json` prior to implementing DocsCI rules.
- **Remediated Scan**: Run `docsci report docs/ --previous baseline.json --output current_report.md` after applying fixes.
- **Metric**: Percentage violation reduction by rule and severity.

### C. AI Claim Verification Catch Rate
- **Verification Audit**: For releases utilizing `docsci release-notes --ai-summary`, record the number of claims generated by the model.
- **Catch Rate**: Track how many unsupported claims, hallucinations, or unverified performance assertions the verifier caught before human review.
- **Metric**: Catch rate = `(Unsupported Claims Caught / Total Inaccurate Claims) * 100%`.
